# Deploy, servers and tests: what shipped

Completed work in this area, oldest first, as written at the time. Reference only: for how things work now read `docs/claude/areas/infra.md` and the code. A later entry can supersede an earlier one.

New entries: a few lines each (what shipped, the migration number, the date, where the code is). No test tallies.

- ✅ pg_cron sweep activated
- ✅ **notificationQueue fire-and-forget** — all three `notificationQueue.add()` calls wrapped as `.catch()` promises; API process no longer crashes when Redis is unavailable
- ✅ **deploy.sh always builds as ubuntu** — both `npm install` and `npm run build` in `deploy_admin()` and `deploy_api()` now run via `sudo -u ubuntu bash -c ...` so dist/ files are never owned by root
- ✅ **Custom domains reach the site** — a tenant's verified domain showed nginx's bare 404: no server block named it, so nginx answered from its default port-80 server (certbot's `return 404` block for the apex). New `scripts/nginx-custom-domain.sh` (server block proxying everything to the API, certificate, redirect names, notes when the app doesn't know the domain). `routes/website.js`: `cleanCustomDomain()` (lower case, no scheme/path/port/trailing dot, hostname only, refuses our own root and another tenant's domain), verification cleared only when the domain changes (the Domain section sends it on every save, so switching Site is live used to take a verified domain offline), `platformIps()` (A records checked against what the site's own address resolves to, `APP_PUBLIC_IPS` optional), `server_status` on dns-setup and verify. Domain section: `DomainServerNotice` (with the command for platform admins), link only once https; guide step 5 no longer claims automatic certificates. Tested against a local nginx with the API behind it (35 checks) and the Domain section in a browser. No migration.
- ✅ **Custom domains switch on by themselves** — the domain sync (`scripts/custom-domains-sync.sh`, systemd timer every minute + a path unit on `/var/lib/macaroonie-domains/kick`, installed by every deploy through `scripts/install-domain-sync.sh`) runs the domain script for each verified domain without an https block: DNS must point only at the server (A records in what the root resolves to + `APP_PUBLIC_IPS`, any AAAA too) else `waiting_dns` with the reason; the www / bare twin goes with it when its DNS points here, or later; failed certificates back off 5 min / 15 min / 1 h / 6 h / daily (a kick retries after 2 min); blocks for domains no tenant has saved are removed with their certificate. State per domain in `<domain>.json`, heartbeat `last-run`, off switch `disabled`. The domain script keeps https for the main name when adding a twin fails, takes a lock, closes it for children. API: verify (when verified) and a domain change write `kick`; dns-setup / verify return `server_auto` + `server_state`. Domain section: progress notice (switching on / waiting for DNS / http only with next try), refetch every 10 s until https, manual command only when the sync isn't running. Tested against a local nginx, Postgres and the API with certbot stubbed (84 checks), the installer (systemd-analyze verify) and the Domain section in a browser (21 checks). No migration.
- ✅ **Deploy health check waits for the API; nginx http2 warning gone** — `.github/workflows/deploy.yml` tries `/api/health` every 2 s for up to 30 s before the final check (the fixed `sleep 3` failed two deploys while the two PM2 processes were still starting). New `scripts/ensure-nginx-http2.sh` in the deploy's nginx step. Tested: the check against a server that starts after 5 s (passes at 6 s) and one that never starts (fails at 30 s), under `set -euo pipefail`; the http2 script against nginx 1.24 with the apex / domain / wildcard mix that produced the warning (gone afterwards, rerun skips, no-http2 address untouched, failed `nginx -t` restores). No migration.
- ✅ **API tests in the repo + the cross-tenant sweep** — the review's Next list (17 Oct 2026), C2. `api/test` (`npm test`, CI job `api-tests`): the real app with a stand-in login (`Bearer test:<sub>`) and a stand-in Claude, two tenants made through the platform route and filled through the API (`fillTenant()`, 120 of 182 tenant tables). The sweep: every route with params as tenant B with A's ids and B's own mixed in (~53,000 calls; leaks by A's mark or ids, changes by an md5 per table, 500s), every write A made sent again as B (also with B's ids swapped into the address), no row of B's holding an id of A's (plus link tables without a tenant_id). Pepper's chat loop ported from the scratch suite (13 tests). **Fixed, found by it**: food-safety equipment / check times / hold stations / cooking sessions / deliveries, checklist templates and reviews took any venue id in the body (now `refuseOtherTenantsVenues` on every route); a table's section, a combination's tables, a staff role, a Cash Recon day's sources / channels / SC sources, a wage week's and wage default's staff (the default returned the other tenant's staff names and pay), online ordering's menus, a dish's option groups and options, an override's sittings (added under another tenant's override) and translation keys all took another tenant's ids; also the team routes' own-user lookups now filter the tenant. No migration. Tested: `npm test` (17 tests, about 90 s); the sweep reported the body venue ids and the mixed-id cases before their fixes (the wage default and translation keys were found by reading the routes it pointed at) and passes after.
- ✅ **CI: the API test that failed one run in three; menu positions** — the user's question (24 Oct 2026): "Looks like last deployment failed?" The deploys had succeeded; the CI "API tests" job had failed four times since 23 Oct (#62, #65, #73, #74). Cause: `ItemBody` / `SectionBody` / `VariantBody` / `ItemGroupAttach` / `CalloutBody` in `routes/menus.js` defaulted `sort_order` to 0, so `upsertMenuTree()`'s `?? index` fallback never ran and a dish sent without a position tied with the first dish; `loadMenuFull()`'s `json_agg(DISTINCT ...)` returns tied dishes ordered by the jsonb (so by random id), and `kiosk-preview-menu.test.mjs`'s last test read `sections[0].items[0]` (the new unpriced dish about one run in three). Fixed: the five schemas take `sort_order` as optional (left out = place in the list), `loadMenuFull()` breaks ties by name then id, the test picks its dish by id, new `api/test/menu-order.test.mjs` (sections, dishes, options, groups, notes and the published copy keep the order sent; ties by name; both mutations caught). CI: `npm test` uses `--test-reporter=spec` (failing tests listed with their errors at the end) and the job sets the Postgres service's `log_min_messages` to fatal, because GitHub prints the service log after the tests and the sweep's expected errors buried the results (and the job log download is blocked from the build environment: only its tail can be read). No migration. Tested: the new test file, the kiosk preview test, the full API suite.
