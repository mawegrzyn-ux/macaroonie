# Till (POS): what shipped

Completed work in this area, oldest first, as written at the time. Reference only: for how things work now read `docs/claude/areas/till.md` and the code. A later entry can supersede an earlier one.

New entries: a few lines each (what shipped, the migration number, the date, where the code is). No test tallies.

- ✅ **Till (POS): table service, counter, offline** *(migration 156)* — built cloud-first with the hub parked (user, 11 Oct 2026: "park testing and hub for now ... provision in code for it"). Event-sourced checks (`shared/pos/checks.js` + `sequencer.js`), sequenced by the cloud per venue under an advisory lock; tills are paired devices (one-time code) with PIN sign-in checked offline; a local-first PWA at `pos.<domain>` (IndexedDB outbox, socket + polling sync, refused offline events listed as conflicts). Table service (floor plan, tabs, covers, seats, courses with hold / fire, modifiers with No / Light / Extra / On the side and nested groups, meal deals, notes and allergies, send, void), discounts / comps / offers (promotions with channel `pos`) / service charge, split / move / merge, pay (external card, cash with change, voucher, account, other; tips; split tenders), refunds, reopen, counter mode with order numbers, X / Z with the Z filling Cash Recon (`recon_map`). Admin: Till setup, Floor plan, Till reports; till fields on Menus, Variant groups and Promotions. Kitchen tickets queue in `pos_print_jobs` for the hub; bills and receipts print from the till's browser. Tested: shared rules / sequencer unit tests, API against a local database with two tenants, the till in two browsers (offline conflict, split, merge, comp, refund, reopen, Z + Cash Recon), the admin pages at 1280 and 1015 px.
- ✅ **Till PINs work as soon as they are set + live updates across API processes** — a PIN set in Till setup didn't sign in on an open till: the till only knew the hashes from its last config, the `pos.config` push reached only sockets held by the same PM2 process (cluster, `instances: max`), and otherwise the till reloads its config every 10 minutes. `config/ws.js` now relays every `broadcast()` through Redis pub/sub (`macaroonie:ws`, origin-tagged so nothing arrives twice; local delivery still works with Redis down), which also fixes timeline / orders pushes. `staffForPin()` (`pos/src/lib/store.js`) fetches the config on a miss (online, at most every 5 s) and looks again. `hashPin()` throws "Open the till at https:// to sign in" without WebCrypto, `PinPad` shows errors instead of hanging on "Checking…", and `routes/posSite.js` redirects the pos host from http to https (X-Forwarded-Proto). Tested with two API processes and Redis (push across processes, Redis down and back, no doubles), the till in Chromium against the other process with pushes cut (new PIN signs in, wrong PIN, insecure origin message), the redirect, and `shared/pos` tests. No migration.
