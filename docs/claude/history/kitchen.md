# Kitchen screens: what shipped

Completed work in this area, oldest first, as written at the time. Reference only: for how things work now read `docs/claude/areas/kitchen.md` and the code. A later entry can supersede an earlier one.

New entries: a few lines each (what shipped, the migration number, the date, where the code is). No test tallies.

- ✅ **Kitchen flow designer, runners, order ready boards per board** *(migration 169)* — Till setup → Kitchen screens → Kitchen flow: boxes (Orders in + stations of kind prep / expo / runner / board) and links with filters (dish, section, revenue centre, order type); from each point a dish takes the most specific links (ties all apply), its whole way worked out when sent (`item.route`), arrival = every node before it done. Expo / runner bumps finish dishes still upstream (`show_upcoming`), recall / undo refused once a later station is done (`moved_on`), remake at prep clears that station onwards, at expo / runner restarts the dish. Ready = every dish has reached its boards and runners; a runner at the end of every dish's way hands the order over (collected). `kds_routes` became `kds_flow_edges` (start links per station, every prep to every expo); kitchen orders cleared. Kitchen screen: From / Then / At labels, Also-on-this-order line, DONE at runners, Ready panel at expos and runners. Order status block: board picker (`opts.board` by name, `boards[name]` in the feed), stacked layout, ready first, preparing box colour, change animation (float / fade / pop / zoom) from the player's `orderChanges()`. Also fixed: the change animation was skipped when the draw fell in the same millisecond as the change (fractional clock offset). Tested: 23 kitchen + 18 screen layout unit tests, 77 API checks (incl. the brief end to end), 31 kitchen screen and 49 admin / player browser checks (1280 / 1015 / 390, view only).
