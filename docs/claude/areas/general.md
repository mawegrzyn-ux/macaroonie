# General gotchas

Covers: React, JSX, CSS, Tailwind and SQL mistakes that are not about one area.

Key files and mistakes to avoid for this area: read it before changing code here. What shipped and when is in `docs/claude/history/general.md`; the index of all areas is in `CLAUDE.md`.

## Mistakes to avoid

> Append-only: never delete an entry, only correct one that turns out to be wrong. New entries go at the end.

- **React hook stability** — always return stable references from custom hooks. Any object/function used in a `useEffect` deps array must be wrapped in `useMemo` / `useCallback` or you get an infinite render loop. This applies to every `useContext`-returned value, every query result object, and every callback passed as a prop.
- **No conditional `useQuery` between an early return and another hook** — React error #310 (`Rendered more hooks than during the previous render`) fires when a component returns early before some hooks, then on a later render reaches those hooks. Pattern that broke `/platform`: `const me = useQuery(...)` → `if (!me?.is_platform_admin) return <Denied/>` → `const tenants = useQuery(...)`. First render `me` is undefined, only 1 hook runs; once `me` loads with `is_platform_admin: true`, 2 hooks run → React aborts. Fix: declare ALL hooks unconditionally at the top, gate the secondary query with `enabled: condition`, and move the early `return` AFTER every hook call.
- **`setAttribute('disabled', false)` STILL DISABLES the button** — browsers treat the presence of the `disabled` attribute as disabled regardless of the value (`'false'` as a string is truthy from HTML's POV). Bit us hard in the reservations widget's `el()` helper (May 2026): an `else if (v != null) setAttribute(k, v)` catch-all ran for `disabled: false`, silently disabling every calendar cell and slot button for hours. The fix: handle `disabled` (and other boolean HTML attributes like `checked`, `readonly`, `required`) explicitly — set the attribute ONLY when the value is truthy. Same idea: in any DOM-builder helper, the catch-all branch must skip falsy values (`v != null && v !== false`) or the boolean-presence trap will catch you again.
- **JSX attribute strings follow HTML rules, not JavaScript string rules — `\'` is NOT a valid escape** — in `hint='You\'re done'`, the `\` is a literal backslash, `'` terminates the attribute, and the parser sees unexpected tokens. esbuild error: `Expected ">" but found "\"`. Fix: use double-quoted attributes (`hint="You're done"`) or JSX expressions (`hint={'You\'re done'}`). Double-quoted attributes handle apostrophes with no escaping needed. Bit us in `ReservationsWidget.jsx` and `SiteBlockEditors.jsx` (May 2026) on `hint='Override "You\'re booked"...'`.
- **A resolved `null` from `useQuery` is not the same as `undefined` — don't collapse them in a guard clause** — `data` is `undefined` while a query hasn't resolved yet, but becomes `null` once it resolves successfully if the API genuinely returns `null` (e.g. `GET .../wages/:week_start` returns `null`, not 404, when no report exists yet for that week). A guard like `if (!wagesData || !config) return` treats "confirmed empty" the same as "still loading" — so logic meant to run on confirmed-empty (auto-populate defaults, show an empty state) never fires. Check `wagesData === undefined` specifically when the success value can legitimately be `null`. Bit us in the Wages page's auto-populate effect.
- **Some touch devices never surface their on-screen keyboard for a text/number input — this is a platform limitation, not something `inputMode` can fix** — confirmed on at least one Linux/Chrome tablet tapping a `type="number" inputMode="decimal"` field. Desktop Linux has no standardised "show virtual keyboard on touch focus" contract the way iOS/Android/ChromeOS do, and Chromium's own virtual-keyboard support on Linux is a long-standing known gap. Don't chase OS-specific workarounds — sidestep it with the same custom on-screen keypad pattern already used for covers entry (`NewBookingModal.jsx`'s `IS_TOUCH` + `CoversInput`/`NumericKeypad`) and now temperature entry (`foodSafety/shared.jsx`'s `TempKeypadModal`): render a button instead of a native input on touch devices, open a full-app keypad UI on tap.
- **Nothing outside `api/` or `admin/` existed before `shared/`** — the admin reaches it through the `@shared` alias and `server.fs.allow` in `vite.config.js` (without `fs.allow` the dev server refuses the import, the production build does not), and Node needs `shared/package.json`'s `"type": "module"` or it parses the file as CommonJS. Keep `shared/` dependency-free: neither app installs packages there.
- **A controlled number input must not clamp `Number(e.target.value)` straight into its value** — `Number('')` is 0, so emptying the field puts 0 back at once and the caret jumps: the operator can't clear it to type a new number. Keep the typed text in local state while focused and pass valid numbers up (see `StepNumberInput` in `BrandLayoutFields.jsx`, `PriceInput` in `components/menus/shared.jsx`).
- **Chrome's print dialog Margins setting (Minimum / None / Custom) replaces the page's `@page` margin** — only "Default" honours it. A sheet that relies on `@page { margin }` alone prints edge to edge when someone picks Minimum. Give the body its own padding as well (see `rotaHtml()` in `rotaExport.js`).
- **A transparent `<input type="date">` laid over a styled button must have `onClick={openPicker}` (`lib/utils.js`)** — on a desktop browser the native date input opens its calendar only from its own icon, which is invisible under `opacity-0`, so clicking the button just focused a hidden field and the date looked impossible to change (reported on Purchasing's Place order). Phones and tablets open the picker on tap either way. Any new date-as-button overlay needs the same handler.
- **A blank admin with the address unchanged and nothing in the console is probably the window scrolled, not a crash** — the shell is `h-screen overflow-hidden` and pages scroll in their own panes, so the window should never scroll; if something makes the document taller (an absolutely positioned element with no positioned parent inside a scrolled pane sits at its unscrolled place) and then gets focus or `scrollIntoView`, the whole app leaves the screen and only the grey page shows. Check `window.scrollY` before hunting for errors. Hidden inputs (`sr-only`) are pinned on screen by `index.css`; still give their label or wrapper `relative`. Playwright's `setInputFiles` / file chooser doesn't return focus to the input the way a real file dialog does, so an upload test passes while the real browser jumps: call `input.focus()` after picking.
- **Pictures inside an editor canvas must not be natively draggable** — a mouse press on an `<img>` starts the browser's own drag, which fires `pointercancel` and ends a pointer-event move after a few pixels (the block snaps back); on an iPad a press and hold opens the picture menu or the system drag. A canvas that moves blocks with pointer events needs `onDragStart={noImageDrag}` and `user-select: none; -webkit-touch-callout: none` on its blocks (both designers have it). `@dnd-kit` sensors cancel `dragstart` themselves.
- **A `<label>` around a row of buttons presses the first button when its text is tapped** — the label forwards the click to its first labelable child. `Field` in `components/staff/shared.jsx` takes `group` for rows of buttons (Segmented, chips, colour swatches, editors with remove buttons): it renders a div with `role="group"`. Use `<Field group ...>` for anything that isn't a single input or select.
- **A fieldset doesn't stop a dropped file** — `ReadOnlyFieldset` disables buttons, but a picture area that takes dropped files (`FileDropArea`, `PicturePick`) needs its own `disabled` for View users, as the kiosk editor's `LockedCtx` and the combo editor's `readOnly` pass.
- **In a migration, bracket a jsonb `->` before `-`, `||` or `?`** — `->` is a generic operator with lower precedence than `-`, so `b->'opts' - 'show_names'` parses as `b -> ('opts' - 'show_names')` and fails with "operator is not unique: unknown - unknown". Write `(b->'opts') - 'show_names'` and `(b->'opts') ? 'show_names'`.
- **The HTML `hidden` attribute loses to any `display` class** — `<button hidden className="inline-flex ...">` shows anyway (Tailwind's `inline-flex` beats the browser's `[hidden] { display: none }`), so a button meant to be hidden for View users was visible (the dish panel's Copy, caught by the browser check). Render it conditionally (`{!readOnly && <button ...>}`); `hidden={readOnly}` only works on elements with no display class.
- **A `truncate flex-1` label in a row of `shrink-0` badges and buttons goes to zero width when the row is narrow** — it shrinks first and never wraps, so a phone (or a tablet with a side panel open) showed rows of prices and buttons with no names. Give the label a `min-w-[…]`, put the rest in one group, and `flex-wrap` the row: the group then goes onto a second line before the label gets narrower than its minimum (`ItemRow` and the section heading in `Menus.jsx`). Test at 390 px with a long name, not only short ones (the mutation check passed with short names alone).
- **Never make a component inside another component's render in the till, kiosk or kitchen apps** (`const Chips = (...) => ...` in a function component's body) — it is a new component type on every render, so React swaps its DOM for new elements each time, and the device apps re-render often by themselves (sync, pulls, clocks): a tap that lands while the button is swapped is lost, and a browser test reading the element can catch it detached. The allergy window's chips were made that way at first (a test's measurement of a chip came back empty in some runs); define such pieces at module level and pass what they need as props.
- **A boolean made with `=` on a nullable column is NULL, and `ORDER BY x DESC` puts NULLs first in Postgres** — the catalogue's `exact` (`lower(i.code) = lower(search) OR EXISTS (...)`) was NULL for every item without our own code, so `ORDER BY exact DESC` put items that only mentioned a code before the one with that code. Wrap such comparisons in `COALESCE(..., false)` (or `IS TRUE`), or say `NULLS LAST`, whenever the result is sorted on.
- **A window that shows what is true now (a check, a dry run, a preview of a change) must load with `staleTime: 0, gcTime: 0`** — the admin's QueryClient keeps answers for 30 s (`main.jsx`), so reopening such a window within 30 s showed the old answer (a code fixed a moment ago still listed as wrong). Lists that refresh themselves are fine with the default.
- **A checkbox's `checked` must be a boolean: `a && b` gives `undefined` when `a` is undefined** — React then treats the box as uncontrolled until it is ticked and warns. The shared dish picker's tick boxes had `checked={itemSet.has(id) || whole}` with `whole = allowSections && ...`, undefined in every picker without sections (the first were the order flow designer's; the browser check's console watch caught it); it is `!!allowSections` now. `Toggle` in `components/pos/shared.jsx` already passes `!!checked`.
- **Tailwind's `line-clamp-N` sets its own `display`, and a `block` (or `flex`) class on the same element undoes the clamp** — `line-clamp-3` is `overflow: hidden; display: -webkit-box; -webkit-line-clamp: 3`, and the display utilities come later in the generated CSS, so `block line-clamp-3` shows every line (the menu search's descriptions ran to seven lines on a phone until the browser check measured them). Put the clamp on an element with no display class (a `<span>` needs none: the clamp makes it a box), keep the whole text in `title`, and check the rendered height in a browser (lines = height / line height), not the class list.
- **Never put an invisible character in source: write its escape** — a byte order mark is `'\uFEFF'` (the CSV exporter's first character), a no-break space `'\u00A0'`. Pasted in as the character itself it can't be seen in a diff or a review, an editor or a tool may strip it without a word, and a test comparing against it then fails for no visible reason.
- **Something typed that isn't a value goes up as "not ready", never as empty, wherever empty means something** — a filter that asks each time treats nothing picked as "everything", so a number box that sent `null` for "abc" let Show (or Add the filter) go ahead and show every row. `NumberBox` sends `NaN`, keeps the text and says Type a number; `filterValueOk()` refuses it. And "nothing picked" has one rule, `blankValue()` in `shared/reports/build.js` (no value, no ticks, both ends of a range empty), used by the viewer's choices and the builder's filter window: two copies disagreed about an emptied range.
- **A message said for a moment must be an overlay, and a status line must keep its place** — the builder's `data-said` (the Data panel's foot) and `builder-said` (the page's foot) are absolutely positioned, and the Save note is always a line (it says Nothing to save rather than going away). A message that takes room moves the shelves under a finger in the middle of a drag, and a bar that changes height moves everything below it. A browser check of a drag must not start while such a message would shift the page either.
- **An icon-only button needs `min-w-[48px]`, and a grip is `w-12`** — `h-12 px-3` with its words hidden below `sm` is 40 px wide on a phone, and a `w-10` drag grip is 40 px wide at every width. The builder's bar buttons, the shelves' and the Data panel's grips and the shared `Modal`'s Close (`components/staff/shared.jsx`, now `h-12 min-w-[48px]`, on every page that uses it) were all under 48 px one way until a check measured width as well as height.
- **A window's starting state is set by the handler that opens it, never in an effect on `open`** — an effect runs after the window's first paint, so it showed the picks from the last time it was open for a frame (the viewer's period, venues and other choice windows: `PeriodPicker.jsx`, `VenuesPicker.jsx`, `ParamInputs.jsx`, found by a browser check that read the window as it opened). Set the draft in the click handler that opens it (`show()`), or mount the window's body only while it is open.
- **React's StrictMode runs effects twice in development, so a one-time restore must remember what it was done for** — the report table's scroll was put back by a layout effect and reset to the top by its second run, so the way back from a record lost the table's place (only in development; production runs effects once). `ResultTable` keeps the shape it last started on in a ref (`drawn`) and the viewer a `restored` ref; a new "put it back as it was" effect needs the same guard, and must be checked under StrictMode (the dev server), not only in a production build.
- **Times written by the database and compared again must be compared in SQL** — postgres.js reads a timestamptz back into a JS `Date`, which keeps milliseconds only, so a flag's `updated_at` read into JS and written back (or compared with another row's) can tie or turn round with the microseconds lost. `foldInto()` picks each person's newest flag and decides whether it is newer than the entry's in one statement for that reason; a stamp the API compares later (`flags_at` against `learned_at`) is written from the API's own clock (`new Date()`) on both sides.
- **`api.download(path)` (`admin/src/lib/api.js`) adds `/api` itself, and its object URL must outlive the click** — pass the route without `/api` (a `path` the API sends that starts with `/api/`, like `fileView()`'s, would become `/api/api/...`), and never revoke the blob's URL in the same tick as the click: some browsers start the save after it, so the download fails (the URL is let go after 30 s).
- **Restore a scroll position only once everything above the list has its final height** — the browser's scroll anchoring moves `scrollTop` when content above the visible part changes height, so a place put back before the permissions loaded (a View notice above the list that then went away) moved by that notice's height and was saved wrong (Local info, 21 Nov 2026). Wait for what decides the page above (`usePermission().loaded`, the data), hold off saving while restoring, and retry a clamped value for a few frames.
- **Send a reply after the transaction, never inside `withTenant()`** (27 Nov 2026, the cost scenarios route) — `return withTenant(id, async tx => { ...; return reply.code(201).send(row) })` sends the answer from inside the callback, before COMMIT. The client (the fixtures, the admin's next request, Pepper's next tool call) can ask for the new row before the commit lands and get a 404. It passed every local run and failed only in CI, under load, in whichever test file happened to lose the race (`PUT /api/cost-scenarios/:id` answered 404 right after the POST). Return the row from `withTenant()` and send it after: `const row = await withTenant(...); return reply.code(201).send(row)`.
