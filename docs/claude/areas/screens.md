# Menu screens

Covers: menu screens, the board designer, playlists, walls, the player, order ready boards.

Key files and mistakes to avoid for this area: read it before changing code here. What shipped and when is in `docs/claude/history/screens.md`; the index of all areas is in `CLAUDE.md`.

## Key files

Under **API**, `src/...` means `api/src/...`; under **Admin portal**, `src/...` means `admin/src/...`. Other paths are from the repo root.

## Mistakes to avoid

> Append-only: never delete an entry, only correct one that turns out to be wrong. New entries go at the end.

- **A menu screen board draws through `shared/screenLayout.js` only, in the player and in the admin designer** — never add block HTML or CSS to `ScreenDesigner.jsx` or `screen/player.js` (the designer may only add placeholders, the selection box and handles), or boards stop looking the same on the screen as in the designer. A new block type goes into `BLOCK_TYPES`, `BLOCK_DEFAULTS`, `renderBlockInner()` and the designer's `BlockPanel`; a new shared file the renderer imports must be added to `PLAYER_LIBS` in `services/screenSvc.js` (and `SHELL_FILES` in `screen/sw.js`), or the player gets a 404 for it and shows nothing. (Corrected 4 Nov 2026: `PLAYER_LIBS` is worked out from the player's imports now, and `sw.js` gets the same list, so nothing is added by hand; see the entry on files a browser loads without a bundler.)
- **The screens host is a platform host (`screens` in `RESERVED_SUBDOMAINS`, `platformHostKind()` 'screens')** — `routes/screenSite.js` answers every GET on it except `/screen-api`, `/ws`, `/uploads/` and `/api/`, so a new path a screen needs (e.g. a media proxy) must be added to its `PASS_PREFIXES`. A screen's secret is never stored by the API (only its sha256, first on the pairing row, then on the screen); don't add a "show the secret" or re-send it anywhere: a lost device is re-paired with a new code (New device for this screen).
- **A screen's board timing comes from the shared clock, never from when its timer fired** — `playlistPosition(list, nowMs())`, `replayStart()`, transition `currentTime = nowMs() - pos.startMs` and `syncVideos()` all read `nowMs()` (device clock + offset from `/screen-api/time`). Code that starts an animation, a video or a board "now" (`Date.now()`, `play()` from the start) puts that screen out of step with the rest of its wall. A new timed effect on boards must take its start from the clock the same way.
- **A screen on a wall gets its board from the wall, not from `screens.design_id` / `playlist_id`** — `screenConfig()` reads the wall first (`source`). Admin code showing what a screen shows must use `screenView()`'s `shows` (it already does) rather than the screen's own columns, and a screen moved to another venue must leave its wall (the PATCH does it).
- **Times compared with a fractional clock must allow for `Date` dropping the fraction** — the screen player's `nowMs()` includes a fractional offset, but `new Date(nowMs())` truncates, so "elapsed since a change" can come out as -0.7 ms when the draw is in the same millisecond; the Order status animation skipped those. Stamp whole milliseconds (`Math.floor(nowMs())`) and treat a tiny negative gap as zero.
- **Anything drawn inside a scaled-down editor canvas shrinks with it: draw thin guides beside it in screen pixels** — the screen designer's grid was a 1px line inside the board, which is `transform: scale()`d to fit (0.2-0.5 usually), so it rendered at a fraction of a pixel and the grid button looked broken for months. Selection boxes, handles, wall guides and the grid sit beside the board and multiply positions by `scale`; only things that must look like the screen (blocks, background) go inside. A style inside that has to stay a fixed screen size divides by `--sd-scale` (`.sd-empty`).
- **A device's Disconnect clears its secret but keeps its row** — `POST /pos-api/disconnect` / `/screen-api/disconnect` set `secret_hash = NULL` (Not paired; New code / New device pairs it again with its settings); removing it in Till setup (`revoked_at`) is the permanent one. A device must never disconnect with sales or paid kiosk orders still in its outbox (pairing again clears the outbox): the till and kiosk refuse, the kitchen screen warns with the count.
- **A key press that opens a panel and moves focus into it must be `preventDefault`-ed** — Chrome activates a focused button on the same Enter / Space press, so the menu screen player's fifth OK press opened its settings and pressed Close in the same moment (the panel looked like it never opened). Any keyboard shortcut that focuses a button as it opens something needs the same.
- **What an order shows on an order ready board tile or a kitchen ticket title comes only from `orderInfo()` / `orderValue()` in `shared/orderInfo.js`** — the tile, the kitchen screen's `ticketTitle()` and the bench all call it, so a new place that names an order (a printed ticket header, a Pepper answer, a report) must too, or it disagrees about which name counts (online guest first, then the till or kiosk name, never a table's tab) and what happens when the chosen field is missing (fall back to number, tent, table, name). A new field goes into `ORDER_FIELDS` and `orderValue()`, and into `boardNumbers()`'s view in `shared/pos/kitchen.js` if boards should show it.
- **A colour can be the word `transparent` (See-through, `clear` on `ColourPicker`)** — only on background fields: board backgrounds and boxes in `shared/screenLayout.js` (`colour()` passes it, `withAlpha()` keeps it) and the kiosk's `CLEAR_COLORS`. Code that reads one of those colours as a hex (contrast maths, `inkOn()`, appending alpha digits, `parseInt(hex.slice(1), 16)`) must handle it first (see `solidColours()` in `KioskDesigner.jsx`, `cleanHex()` in `shared/themeKit.js`); don't offer `clear` on a field whose colour is also used for text.
- **An order board tile is `.sl-onum` > (`img.sl-oicon`) + `.sl-otext` > caption / value / lines** — the look comes only from the custom properties `tileLook()` puts on `.sl-orders` (`shared/screenLayout.js`); a new tile option needs a property there and a rule in `SCREEN_LAYOUT_CSS`, never inline styles per tile, and any picture it adds must go through `tileImageUrls()` or screens show it late and lose it offline. Tests that match tile HTML must expect the `.sl-otext` wrapper.
- **`config/ws.js`'s paired-screen branch takes any connection naming a `screen`, so a new connection kind that names one too must be excluded from it** (the live view's boards: `!url.searchParams.has('board_live')`), or it is refused as an unpaired screen (4003) before reaching its own branch.
- **The menu screen player in live mode must keep nothing on the device: everything it stores goes through `save()`, which does nothing when `LIVE`** — a browser that is also a paired screen keeps its pairing and config in the same localStorage, and a live board writing there would replace the screen's config with the live view's board (or its pairing with nothing). Don't call `localStorage` directly in `screen/player.js`.
- **An order ready board filters by what `boardNumbers()` puts on each entry, so a new filter needs the field on the entry first** (6 Nov 2026) — the Order status block filters in the renderer (`orderFilter()`), on the venue's whole feed, by `type_name` and `stream` (names, because boards are shared by every location). A filter on something an entry doesn't carry silently hides every order. Add the field to the kitchen order (`newOrder()` defaults, `headerFromCheck()`, `refreshHeader()`'s keys, `kitchen.order_in` and `onlineOrderProblem()`), then to `boardNumbers()`' view; a check event that changes it must be in `KITCHEN_CHECK_EVENTS`, or the order keeps the old value. Orders already in the kitchen when such a field ships don't have it.
- **A result's cells are everyday values and its labels are words: handle the row's kind before formatting** — money in pounds, a percentage as a fraction, a duration in seconds, a day as `YYYY-MM-DD`, a moment as the venue's wall time with no zone (`2026-10-19T18:15:00`: read its parts as written, never through `new Date()` and a time zone again). The "everything else" row and the Subtotal / Total rows carry words in typed columns ("Every other dish" in a date column), so the page (`ResultTable`) and the files (`export/table.js`) look at `row.kind` first. A cell is 0 where rows exist but none count for the figure and empty where there are no rows: don't turn one into the other.
