## 1. Generative UI: the main approaches and standards, how mature they are, declarative versus free-form

### Takeaway
By late 2026 the field has settled on three tiers: controlled (the model picks a hand-built component and fills it), declarative (the model emits a JSON description that the client renders from a trusted component catalogue: A2UI, Adaptive Cards, ChatKit widgets, Salesforce's structured UI) and open-ended (the model or a tool returns HTML or code that runs in a sandbox: MCP Apps, the OpenAI Apps SDK, Claude artifacts, Google's dynamic view). Business products that change real data ship the first two; free-form generation at run time is still slow (a minute or more at Google), occasionally wrong or non-functional, and is used mainly for one-off visualisations and for build-time "describe an app" builders.

### Cited Findings

**The taxonomy**
- [V] CopilotKit's 2026 guide names three types. Static (called "Controlled" in newer docs): the frontend owns the UI, the agent only chooses a predefined component and fills it; "the agent never controls layout or invents UI". Declarative: the agent returns a structured description (cards, lists, forms) and the frontend renders it; named specs are A2UI (Google, JSONL streaming) and Open-JSON-UI (an open standardisation of OpenAI's internal schema). Open-ended: the agent supplies raw markup (HTML and CSS), delivered through MCP Apps; "most freedom but requires careful security measures". Vendor framing, not independent. — [CopilotKit, The Developer's Guide to Generative UI in 2026](https://copilotkit.ai/blog/the-developer-s-guide-to-generative-ui-in-2026); [same on DEV](https://dev.to/copilotkit/the-developers-guide-to-generative-ui-in-2026-1bh3)
- [V] AG-UI is the runtime layer under all three: it "doesn't dictate the UI pattern or specification format" and only provides the agent-to-frontend connection. — [CopilotKit generative-ui repo](https://github.com/CopilotKit/generative-ui)
- [PK] AG-UI was introduced by CopilotKit in May 2025 as an event-based agent-to-frontend protocol and has integrations for LangGraph, CrewAI, Mastra, Pydantic AI, Microsoft Agent Framework and Google ADK. — [AG-UI docs](https://docs.ag-ui.com/)

**Declarative: the model fills a schema from a catalogue**
- [V] Google A2UI: agents send a declarative JSON description; the client renders it with its own native components (Flutter, Angular, Lit and others). The catalogue is the contract: the client keeps a catalogue of trusted, pre-approved components and the agent can only request components from it. Google describes it as "a declarative data format, not executable code". — [Google Developers Blog, Introducing A2UI](https://developers.googleblog.com/en/introducing-a2ui-an-open-project-for-agent-driven-interfaces/)
- [V] A2UI maturity: introduced December 2025; the official repo says the v1.0 specification is a release candidate and v0.8 is legacy; v0.9 added a three-step catalogue negotiation handshake (clients declare supported catalogue ids) and custom catalogues for a design system; Android's official Jetpack Compose renderer supports v0.9.1; a Lynx renderer exists. Sources disagree on whether a final 1.0 has shipped. — [google/A2UI](https://github.com/google/A2UI); [CopilotKit, A2UI v0.9: What's New](https://copilotkit.ai/blog/a2ui-whats-new-in-google-generative-ui-spec); [Android Developers, Agent-to-UI renderer for Jetpack Compose](https://developer.android.com/develop/ui/compose/agentic); [Lynx A2UI](https://lynxjs.org/react/genui/a2ui)
- [V] Microsoft Adaptive Cards: "platform-agnostic UI snippets written in JSON" that a host turns into native UI adapted to its context. Copilot Studio agents use them to ask questions and validate information; Microsoft's agent design guidance says a card can use inputs, dropdowns and choice sets "to gather everything they need in a single step". — [Microsoft Learn, Adaptive Cards overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/adaptive-cards-overview); [Microsoft Learn, Adaptive Cards for agent design](https://learn.microsoft.com/en-au/agents/design-guidelines/adaptive-cards-for-agent-design)
- [V] Salesforce Agentforce renders structured UI components from LLM responses in production: more than 4 million sessions and 133,223 agents "generating surface-enabled experiences". Lessons reported by the engineering team: early on the system "frequently over-formatted responses", so even "yes" or "no" appeared as UI components; converting too much makes the interface restrictive, keeping everything as text loses the benefit; limiting the number of options within a component stabilised it; formatting decisions must not change the meaning of the conversation or restrict user choices. — [Salesforce Engineering, How Agentforce converts LLM responses into structured UI across 4M sessions](https://engineering.salesforce.com/how-agentforce-converts-llm-responses-into-structured-ui-for-ai-agents-across-4m-sessions/); [Salesforce Engineering (second post)](https://engineering.salesforce.com/?p=8181)
- [V] Salesforce Generative Canvas: a Lightning feature that "generates a full-screen experience dynamically", grounded in approved Lightning components and existing permissions rather than generating UI from scratch; an earlier post described it as a pilot. The Agentforce Experience Layer (TDX and Dreamforce 2026) lets a developer define one UI that adapts across Slack, ChatGPT and Salesforce, separate from the underlying metadata and actions. — [Salesforce blog, Generative Canvas](https://www.salesforce.com/blog/generative-canvas-lightning/); [Salesforce Ben, Salesforce's vision for the agentic UI is dynamic and personal](https://www.salesforceben.com/salesforces-vision-for-the-agentic-ui-is-dynamic-and-personal/)
- [V] OpenAI ChatKit (generally available since DevDay, October 2025): a widget is "a structured block of UI that the assistant emits as part of its response, rendered natively by the ChatKit front end"; a June 2026 third-party guide calls forms the main use case and recommends a unique key with server-side de-duplication for widget submissions. — [Osher, ChatKit widgets](https://osher.com.au/blog/chatkit-widgets/); [Constellation Research on DevDay 2025](https://www.constellationr.com/insights/news/openai-sets-sdks-app-integrations-agentic-ai-building-blocks)
- [V] Vercel AI SDK: development of AI SDK RSC (`streamUI`, which streamed React Server Components chosen by the model) "is currently paused", with a migration guide off it. — [Vercel template, rsc-genui](https://vercel.com/templates/ai/rsc-genui)
- [PK] The AI SDK's current generative UI pattern is the controlled one: tool calls are mapped to React components in the client (`useChat`). Vercel Labs also published json-render (early 2026), which constrains model output to a JSON tree over a developer-defined component catalogue; existence not confirmed in this session. — [AI SDK docs, Generative User Interfaces](https://ai-sdk.dev/docs/ai-sdk-ui/generative-user-interfaces); [vercel-labs/json-render](https://github.com/vercel-labs/json-render)

**Structured input requested by a tool: MCP elicitation**
- [V] MCP elicitation, form mode: a server collects structured data through the client by sending a `requestedSchema`; requests with no `mode` are form mode. URL mode (added in the 2025-11-25 spec) sends the user to an external page for interactions that must not pass through the client. Servers "MUST NOT use form mode for sensitive information such as passwords, API keys, access tokens, or payment credentials". Clients declare which modes they support, and servers must not send unsupported modes. A 2026-07-28 spec revision of the page exists. — [MCP spec 2025-11-25, Elicitation](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation); [MCP spec 2026-07-28, Elicitation](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation); [SEP-1036 URL mode](https://modelcontextprotocol.io/seps/1036-url-mode-elicitation-for-secure-out-of-band-intera.md)
- [PK] Elicitation arrived in the 2025-06-18 spec; the schema is deliberately limited to a flat object of primitive fields (string, number, integer, boolean, enum), and the user can accept, decline or cancel. — [MCP spec 2025-06-18, Elicitation](https://modelcontextprotocol.io/specification/2025-06-18/client/elicitation)
- [V] Adoption: a vendor guide says form mode is "close to universal among clients that implement elicitation at all"; the pattern has spread to the Agent Client Protocol (its own elicitation pages, v1 and v2) and AWS Bedrock AgentCore's gateway documents it. — [Vercel, MCP elicitation: form vs URL mode](https://vercel.com/i/mcp-elicitation-form-vs-url-mode); [Agent Client Protocol, Elicitation](https://agentclientprotocol.com/protocol/v2/elicitation); [AWS, AgentCore gateway MCP elicitation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-mcp-elicitation.html)

**Open-ended: HTML or code in a sandbox**
- [V] MCP Apps: proposed as SEP-1865 in November 2025 jointly by Anthropic, OpenAI and the MCP-UI community (drawing on the Apps SDK and MCP-UI); announced as an official, production-ready extension on 26 January 2026. Tools can return interactive UI (dashboards, forms, multi-step workflows) rendered in the conversation. Extension id `io.modelcontextprotocol/ui`; optional, negotiated per client and server; the first spec supports only `text/html` in sandboxed iframes talking to the host over MCP JSON-RPC. — [MCP blog, 26 Jan 2026](https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/); [SEP-1865](https://modelcontextprotocol.io/seps/1865-mcp-apps-interactive-user-interfaces-for-mcp); [MCP blog, 21 Nov 2025](https://blog.modelcontextprotocol.io/posts/2025-11-21-mcp-apps/)
- [V] Microsoft shipped MCP Apps support in Microsoft 365 Copilot in April 2026 (real web UI in a sandboxed iframe, against the declarative card schema); as of June 2026 widget rendering was supported only in declarative agents built with the Agents Toolkit for VS Code. — [Andrew Connell, What are MCP Apps? Interactive widgets in Copilot Chat](https://www.andrewconnell.com/articles/microsoft-365-copilot-mcp-apps-01-interactive-widgets/)
- [V] OpenAI Apps SDK (announced October 2025) sits on MCP: tool results carry metadata, including inline HTML, that ChatGPT renders as widgets beside the assistant's messages. OpenAI's reference now says new UI should use the shared MCP Apps bridge where it has an equivalent and `window.openai` only for ChatGPT-specific features. Changelog: MCP Apps compatibility (February 2026), host CSS variables so widgets match the host theme (May 2026), `_meta.ui.visibility` to say whether a tool is available to the model, the app or both (July 2026). — [OpenAI Apps SDK changelog](https://developers.openai.com/apps-sdk/changelog); [OpenAI Apps SDK reference](https://developers.openai.com/apps-sdk/reference)
- [V] Google generative UI (November 2025, Gemini 3 Pro; paper "Generative UI: LLMs are Effective UI Generators"): the model designs and codes a custom interactive response per prompt ("dynamic view" in the Gemini app, and in AI Mode for US AI Pro and Ultra subscribers). In Google's preference study, sites designed by human experts ranked highest, "followed closely" by generative UI, with "a substantial gap from all other output methods" (top Search result, raw LLM text). The evaluation "did not take into account generation speed"; Google says the implementation "can sometimes take a minute or more to generate results, and there are occasional inaccuracies in the outputs". — [Google Research blog](https://research.google/blog/generative-ui-a-rich-custom-visual-interactive-user-experience-for-any-prompt/); [paper](https://arxiv.org/pdf/2604.09577)
- [V] Anthropic: "Imagine with Claude" (September 2025, with Sonnet 4.5) was a five-day research preview for Max subscribers that generated an interface on the fly with no fixed codebase; reviewers reported bugs such as "often failing to implement the functionality of a button". In March 2026 Anthropic rolled a descendant into chat as a beta: interactive charts and visualisations generated inline (not in the side panel), on by default, labelled temporary, Claude deciding when one helps. — [The Decoder](https://the-decoder.com/claude-can-now-create-interactive-charts-and-visualizations-directly-in-chat/); [The Register, 13 Mar 2026](https://www.theregister.com/2026/03/13/claude_charts_a_new_course/); [TestingCatalog](https://www.testingcatalog.com/anthropic-experiments-with-an-agent-for-gereating-ui-on-the-fly); [DataCamp tutorial](https://datacamp.com/tutorial/imagine-with-claude)
- [PK] Claude artifacts (June 2024, generally available August 2024; older) put model-written code or documents in a panel beside the chat. — [Anthropic, Artifacts](https://www.anthropic.com/news/artifacts)

**Build-time generation (a person describes a screen, the platform generates and keeps it)**
- [V] ServiceNow Experience Generation (Now Assist, in UI Builder: Create, then AI-generated experience) "creates fully functional, multi-page ServiceNow experiences from plain-English descriptions". ServiceNow AI Experience (September 2025) is positioned as "the new user interface" and entry point; Knowledge 2026 added "Otto" (conversational AI, autonomous workflows and enterprise search in one experience), with one analyst calling it AIx, "AI becomes the platform UI". — [ServiceNow docs, Experience Generation](https://www.servicenow.com/docs/r/zUlSbxoxKPAWFDGUdAoSCw/Yh2z7SmzcIlQ4wMpeKqZdQ); [ServiceNow press release via Nasdaq](https://www.nasdaq.com/press-release/servicenow-turns-enterprise-ai-chaos-control-platform-governed-autonomous-work-2026); [Constellation Research, Knowledge 2026](https://www.constellationr.com/insights/news/servicenow-knowledge-2026-ai-control-tower-action-fabric-autonomous-workforce-and)
- [V] Shopify Sidekick (Winter '26 Edition, December 2025) generates custom admin apps from a prompt using Shopify's own UI framework and GraphQL API; merchants test and refine them inside the admin before installing. Shopify's MCP UI components deliver commerce components consistently across agents. — [Shopify, Winter '26 Edition for merchants](https://www.shopify.com/news/winter-26-edition-merchant); [Shopify, Winter '26 Edition for developers](https://www.shopify.com/news/winter-26-edition-dev)
- [PK] Microsoft Power Apps "generative pages": a maker describes a page for a model-driven app and an agent writes the React page. — [Microsoft Learn, generative pages](https://learn.microsoft.com/en-us/power-apps/maker/model-driven-apps/generative-pages)
- [V] Notion: Custom Agents launched 24 February 2026 (Notion 3.3, public beta, Business and Enterprise), run on triggers or schedules, connect to Slack, Figma, Linear and HubSpot over MCP; early testers built over 21,000 agents; charged in credits from 4 May 2026; 3.4 (April) added AI Autofill in databases. Notion's AI work is agents over its existing blocks and databases, not generated screens. — [Notion, Introducing Custom Agents](https://www.notion.com/blog/introducing-custom-agents); [Notion release 3.3](https://www.notion.com/releases/2026-02-24); [Notion release, April 2026](https://www.notion.com/releases/2026-04-14)

**Preference evidence for generated interfaces**
- [V] "Generative Interfaces for Language Models" (Chen, Zhang, Zhang, Shao, Yang; Stanford; Findings of ACL 2026): human raters chose generated interfaces over chat responses in over 70% of comparisons; they "excel in structured and information-dense domains", favoured for visual organisation, interactivity and lower cognitive load. Preference ratings, not task performance. — [arXiv 2508.19227](https://arxiv.org/abs/2508.19227); [ACL Anthology](https://preview.aclanthology.org/ingest-acl/2026.findings-acl.74/)
- [V] A practitioner argument for a shared declarative standard: teams now ship "the same form four different times" (web, mobile, chat, agent). — [UX Collective, The call for an agentic standard](https://uxdesign.cc/the-call-for-an-agentic-standard-we-need-to-stop-shipping-the-same-form-four-different-times-be5b9d40e370)

### Inferences
- Classification from the findings above. Controlled or declarative (model picks components, fills a schema): Vercel AI SDK tool-to-component, A2UI, Adaptive Cards, ChatKit widgets, Open-JSON-UI, Agentforce structured UI and Generative Canvas, MCP elicitation forms, json-render. Free-form markup or code in a sandbox: MCP Apps and MCP-UI, OpenAI Apps SDK widgets, Claude artifacts and Imagine, Google dynamic view. Build-time generation reviewed by a person: ServiceNow Experience Generation, Shopify Sidekick apps, Power Apps generative pages. Note that MCP Apps and Apps SDK widgets are usually written by developers and shipped with a tool, so they are "free-form" in format but not generated per request.
- Every vendor that puts generated UI in front of business users who change records (Salesforce, Microsoft, ServiceNow, Shopify) constrains the model to its own approved components and permissions. Free-form run-time generation is confined to read-only answers and visualisations (Google, Anthropic). That is the strongest signal on what is considered safe to ship.
- For a product that already owns its component library and its tools, the controlled and declarative tiers are the mature choice: a catalogue of the product's own cards and forms that the assistant fills. MCP elicitation is the closest thing to a cross-vendor standard for "the tool needs these fields", but its flat, primitive-only schema will not express a nested business form (lines on an order, a rota week) by itself.
- The Salesforce lesson generalises: the hard problem is not rendering but deciding when a component beats a sentence. Expect to tune that boundary with evaluation, and to cap choices per component.
- Latency: a declarative payload is a short JSON object and streams in the time of an ordinary tool call; a fully generated page took Google up to a minute or more. On a tablet at a host stand that difference decides the matter.
- Accessibility and consistency follow the tier: declarative output inherits the host's components (touch targets, focus order, theming); generated HTML in an iframe inherits nothing unless the host passes style variables (OpenAI added these only in May 2026).

### Gaps
- No independent benchmark was found comparing the tiers on error rate, latency or accessibility; practitioner statements come from vendors with a stake. The planned search on A2UI production experience did not run.
- A2UI's final 1.0 status and its production users (Gemini Enterprise, Flutter GenUI SDK were on the list) are unconfirmed.
- Which hosts render MCP Apps today, beyond ChatGPT and partial Microsoft 365 Copilot support, was not confirmed; nor whether MCP Apps was folded into the 2026-07-28 core spec (secondary sources say so).
- Airtable (Omni) and Retool (agents, generated apps): the search returned nothing and was not repeated. No findings.
- No published accessibility audit of generated interfaces was found.

## 2. Dynamic forms: schema-driven rendering, LLM prefill, conversational filling versus a visible form

### Takeaway
The pattern that ships is "the model fills a real, visible form and the person checks and submits it", not a slot-by-slot conversation: every platform's form primitive (Adaptive Cards, ChatKit widgets, MCP elicitation, A2UI) presents all fields at once. Controlled evidence is thin and mixed: conversational input tends to lower perceived effort, does not reliably cut task time, and in the one small voice-versus-GUI data-entry study the GUI was faster.

### Cited Findings
- [V] The platform primitives all show a whole form in one step: Microsoft says a card should "gather everything they need in a single step"; ChatKit widgets are mostly used for forms; MCP form-mode elicitation sends one schema and gets one structured answer. — [Microsoft Learn, Adaptive Cards for agent design](https://learn.microsoft.com/en-au/agents/design-guidelines/adaptive-cards-for-agent-design); [Osher, ChatKit widgets](https://osher.com.au/blog/chatkit-widgets/); [MCP spec, Elicitation](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation)
- [V] Hybrid CRUD study (Dizon, August 2026, N=73, between subjects): a content management system with an LLM agent over MCP, compared as Traditional-only, AI-first and Hybrid across 16 scenarios. The authors conclude the main benefit "may be lower interaction effort rather than faster task completion"; delegation tracked the user's own characteristics more than the task; and there was no significant link between operation type and delegation, so users "did not appear to avoid delegating riskier actions". — [arXiv 2608.19551](https://arxiv.org/pdf/2608.19551)
- [V] Voice CMS study (2025, N=7): updating a knowledge base by voice conversation versus a GUI. The GUI had shorter average processing times (M = 179 s, SD = 124 s) than voice (M = 204 s, SD = 134 s); objective performance was comparable. — [arXiv 2505.22303](https://arxiv.org/pdf/2505.22303)
- [V] Form-based app versus a generative-AI voice prototype for public service access in India (HCINLP 2025, 15 low-income participants): measured usability, completion time and preference; results were not in the extract. — [ACL Anthology, HCINLP 2025](https://preview.aclanthology.org/setup/2025.hcinlp-1.6)
- [V] Older: a University of Oregon thesis comparing a conversational with a traditional search interface found no accuracy advantage either way and better time efficiency for the traditional interface. Perakakis and Potamianos (2008) on multimodal form filling note in their background that GUIs "have low error rates and offer easy error correction". — [University of Oregon thesis](https://scholarsbank.uoregon.edu//bitstreams/9a7d800c-0865-41dd-8c8e-74277c9eacb9/download); [Perakakis and Potamianos 2008](https://slp-ntua.github.io/potam/preprints/journal/2008_perakakis_potamianos_draft.pdf)
- [V] Counter-example: StatZ, a conversational agent for statistical analysis, is reported by its authors to outperform GUI statistics software on completion time and accuracy; sample and design were not in the extract. — [arXiv 2502.08114](https://arxiv.org/abs/2502.08114)
- [PK] DirectGPT (Masson et al., CHI 2024; older): adding direct manipulation (select the object, drag, toolbar of reusable prompts) to an LLM made participants 50% faster with 50% fewer and 72% shorter prompts than ChatGPT. — [arXiv 2310.03691](https://arxiv.org/abs/2310.03691)
- [PK] Older (2016): speech entry on a phone was 3.0 times faster than the keyboard for English with a 20.4% lower error rate (Stanford, Baidu). Lab text entry, quiet room. — [arXiv 1608.07323](https://arxiv.org/abs/1608.07323)

### Inferences
- "One sentence, photo or voice note fills the form, then you check it" combines the strengths the studies point at: language for getting many values in at once (lower effort), the form for overview, verification and correction (where the GUI wins). It also keeps one validation path, since the same form is saved either way.
- The gain from conversational entry should be expected in effort and reach (hands busy, on a phone, do not know where the page is), not in seconds saved by a practised user at a well-designed form. Any business case built on speed needs its own measurement.
- The finding that people delegate risky operations as readily as safe ones means the product, not the user, has to apply the extra friction to destructive changes.
- A schema-driven form generated from a platform's data model is a rendering question (well understood); the LLM adds prefill and field selection. The two should be evaluated separately: the first for consistency, the second for accuracy of the prefilled values.

### Gaps
- No controlled study was found of LLM-prefilled forms versus manual entry in business software reporting error rates; the dedicated search did not run. This is the largest evidence gap for the forms thesis.
- No published completion-time or error data from vendors (Microsoft, Salesforce, ServiceNow, Shopify) on their form cards.
- No study found on photo-to-form (invoice, delivery note, menu) accuracy as experienced by users, as opposed to model benchmarks.

## 3. Natural-language navigation and command patterns: what has stuck, what was withdrawn

### Takeaway
What has stuck is natural language as an additional way in: an "ask" row inside the existing command palette or search, and an assistant that can open the right page or carry out a small task with a confirm. Attempts to make language the only way in have been walked back or adopted slowly (Microsoft 365 Copilot's low use, drive-thru voice ordering, ServiceNow's and Salesforce's "AI as the UI" still described as pilots).

### Cited Findings
- [V] Stripe Dashboard assistant: opened from the help icon, in a drawer; answers questions by retrieval over docs; performs tasks in the Dashboard, for example creating a product and then a payment link, "you only need to confirm". At Sessions 2026 Stripe extended it to payments analytics (investigates performance issues, diagnoses root causes, recommends next steps). Stripe Console (preview, terms dated 29 April 2026) is "the AI-native execution environment embedded in the Stripe Dashboard" for natural-language queries and deploying agents or workflows. — [Stripe docs, Assistant](https://docs.stripe.com/assistant); [Stripe, Everything we announced at Sessions 2026](https://stripe.com/blog/everything-we-announced-at-sessions-2026); [Stripe Console preview terms](https://stripe.com/legal/stripe-console)
- [V] AI inside the command palette, 2025 to 2026: Hashnode's Cmd+K shows an AI suggestion above the search results that "takes you to the place you described" (28 July 2026); Clerk's command menu understands plain-language descriptions (6 November 2025); Sentri shows an "Ask AI" row only when a query does not match a command well; a WordPress pull request makes the assistant the Cmd+K palette and gives it a `run_command` tool to execute palette actions. — [Hashnode changelog](https://hashnode.com/changelog/2026-07-28-ai-navigation-cmd-k); [Clerk changelog](https://clerk.com/changelog/2025-11-06-command-menu); [Sentri docs](https://rameshbabuprudhvi.github.io/sentri/docs/guide/command-palette.html); [WordPress openstation PR 352](https://github.com/WordPress/openstation/pull/352)
- [V] Shopify Sidekick moved from suggesting to doing: previously "a merchant had to navigate the admin to execute a suggested action themselves"; it now executes, and gives contextual answers when the merchant clicks on a specific area of the admin. — [Retail Brew, 11 Dec 2025](https://www.retailbrew.com/stories/2025/12/11/shopify-plugs-in-more-ai-power-to-merchant-assistant); [Shopify, Winter '26 Edition](https://www.shopify.com/news/winter-26-edition-merchant)
- [PK] Shopify's engineers on Sidekick (August 2025): tool sprawl degrades an assistant; up to about 20 tools boundaries stay clear, 20 to 50 they blur, above 50 there are several ways to do the same thing and the system becomes hard to reason about; their answer was "just-in-time instructions" delivered with tool results. — [Shopify Engineering, Building production-ready agentic systems](https://shopify.engineering/building-production-ready-agentic-systems)
- [V] Evidence against language as the main entry point. - "Deep link into the existing page" is the lowest-risk form of natural-language navigation: the answer is a place the user can see, learn and return to without the assistant, so it teaches the GUI instead of hiding it.
- With around 150 tools, Shopify's thresholds suggest tool routing, not the model, will limit "ask to do anything": grouping tools by area and giving instructions only when a tool is in play is the published remedy.

## 4. Hybrid patterns shipping in serious business products

### Takeaway
The products with real usage combine a conventional GUI with AI in five recurring placements: a side panel or drawer, structured cards inside the conversation, a canvas or generated view beside or instead of the chat, proactive briefings and scheduled agents, and an inbox or board for reviewing what agents did. Reported numbers are vendor counts of activity (sessions, agents built), not outcome measures.

### Cited Findings
- [V] Side panel or drawer on top of the existing admin: Stripe's assistant (drawer from the help icon), Shopify Sidekick (contextual to the area clicked), Microsoft 365 Copilot. — [Stripe docs](https://docs.stripe.com/assistant); [Shopify Winter '26](https://www.shopify.com/news/winter-26-edition-merchant)
- [V] Structured cards in the conversation: Agentforce (4 million+ sessions), Adaptive Cards in Copilot Studio, ChatKit widgets, MCP Apps in Claude, ChatGPT and Copilot. — [Salesforce Engineering](https://engineering.salesforce.com/how-agentforce-converts-llm-responses-into-structured-ui-for-ai-agents-across-4m-sessions/); [MCP blog](https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/)
- [V] Canvas or output-first layout: Luke Wroblewski (June 2025) describes layouts where chat shrinks to a side pane and the output takes most of the screen, because agent capabilities make "back-and-forth chatting to get things done feel archaic"; Salesforce Generative Canvas generates a full-screen view from approved components; Anthropic went the other way in March 2026 and put generated visualisations inline in the chat flow instead of the side panel. — [Wroblewski, The Receding Role of AI Chat](https://www.goodreads.com/author_blog_posts/25804020-the-receding-role-of-ai-chat); [Salesforce, Generative Canvas](https://www.salesforce.com/blog/generative-canvas-lightning/); [The Decoder](https://the-decoder.com/claude-can-now-create-interactive-charts-and-visualizations-directly-in-chat/)
- [V] Proactive and scheduled: Shopify describes Sidekick as evolving "from a basic chatbot into a proactive AI agent" that delivers operational insights; Notion Custom Agents run on triggers or schedules without a prompt (21,000 built by early testers); Stripe's assistant investigates payment performance issues and recommends next steps. — [Inside Retail](https://insideretail.com.au/digital/sidekick-agentic-storefronts-simgym-how-shopifys-latest-edition-harnesses-ai-202512); [Notion](https://www.notion.com/blog/introducing-custom-agents); [Stripe Sessions 2026](https://stripe.com/blog/everything-we-announced-at-sessions-2026)
- [PK] ChatGPT Pulse (September 2025): a daily set of briefing cards prepared overnight from the user's history and connected apps; the consumer reference for a proactive feed. — [OpenAI, Introducing ChatGPT Pulse](https://openai.com/index/introducing-chatgpt-pulse/)
- [V] Agent inbox, board or review queue: Wroblewski argues that managing several agents needs "kanban boards, dashboards, inboxes, task lists and calendars" presenting agent state; Smashing Magazine's summary of his view is that users increasingly orchestrate and there is "a lot less chatting back and forth". — [Wroblewski's blog (mirror)](https://www.goodreads.com/author/show/338694.Luke_Wroblewski/blog?page=2); [Smashing Magazine, Design Patterns for AI Interfaces, July 2025](https://www.smashingmagazine.com/2025/07/design-patterns-ai-interfaces/)
- [PK] Examples of the review-queue pattern: GitHub Agent HQ's "mission control" for assigning and reviewing agent work (October 2025); LangChain's "ambient agents" with an agent inbox for notify, question and review interrupts (January 2025). — [GitHub blog](https://github.blog/news-insights/company-news/welcome-home-agents/); [LangChain blog](https://blog.langchain.com/introducing-ambient-agents/)
- [V] Dynamic views assembled per question: Google's dynamic view and AI Mode generative UI; Salesforce Generative Canvas; Claude's inline charts. — [Google Research blog](https://research.google/blog/generative-ui-a-rich-custom-visual-interactive-user-experience-for-any-prompt/)
- [V] Sentiment check: NN/g's State of UX 2026 is reported as finding product teams wary of AI experiences that feel "rushed, confusing, or disconnected from what users actually need" (AI fatigue); an NN/g survey of 521 UX practitioners found AI sped up tasks but sentiment averaged 3.57 out of 5 with mostly negative comments. Secondary coverage. — [DesignRush on State of UX 2026](https://news.designrush.com/ai-fatigue-product-teams); [NN/g, AI in UX survey 2026](https://www.nngroup.com/articles/ai-in-ux-survey-26/)
- [V] Salesforce Ben reports that most organisations interviewed about agentic UI were still in pilots. — [Salesforce Ben](https://www.salesforceben.com/salesforces-vision-for-the-agentic-ui-is-dynamic-and-personal/)

### Inferences
- A "today" feed of exceptions with one-tap actions, a side assistant that opens pages and forms, and confirm cards are squarely in the mainstream of what Stripe, Shopify, Salesforce and Notion ship. The step those vendors are taking in 2026 is scheduled and proactive agents plus a place to review their work, not replacing the GUI.
- Proactive briefings shift the articulation burden from the user to the system (the user reacts instead of composing), which is the best fit for shift leads and chefs who will not type prompts.
- Vendor metrics measure supply (agents built, sessions) and should not be read as evidence of time saved.

### Gaps
- No engagement or outcome data found for proactive feeds (Sidekick, Pulse); the search did not run.
- Intercom, Airtable, Linear and Microsoft Dynamics examples named in the brief were not researched for lack of search budget.

## 5. Design guidance and empirical evidence: when conversational input beats, complements or loses to GUI

### Takeaway
The published guidance converges on hybrid: language is strong for expressing a goal across many steps or when the user does not know where to go, weak for discovery, precision, overview and verification, and it excludes people who cannot put the need into words. The 2025 to 2026 controlled studies agree: chat lowers perceived effort and sometimes time on simple lookups, the advantage shrinks as tasks get complex, accuracy is no better, and users do not want chat as the sole basis for decisions.

### Cited Findings

**Empirical studies, 2025 to 2026**
- [V] "Neither Replacement nor Panacea" (2026): 134 industrial decision-makers, mixed factorial design, three tasks of rising complexity, LLM conversational interface versus graphical dashboard. Perceived workload was lower with the conversational interface overall, but its advantages "diminished as task complexity increased"; neither interface had a consistent accuracy advantage; the conversational interface "was not preferred as a sole basis for subsequent decisions"; self-reported data literacy did not reliably moderate the effects. — [arXiv 2605.31287](https://arxiv.org/pdf/2605.31287)
- [V] Companion exploratory study (N=20, four simulated industrial decision tasks): completion time significantly favoured the chatbot in only two of four tasks; the agent "can reduce interactional effort by supporting more direct access to information, while the dashboard remains valuable for overview and verification". — [arXiv 2605.31224](https://arxiv.org/abs/2605.31224)
- [V] Hybrid CRUD study (N=73, August 2026): lower interaction effort, not faster completion; users delegate risky and safe operations alike (see section 2). — [arXiv 2608.19551](https://arxiv.org/pdf/2608.19551)
- [V] Generated interfaces beat plain chat answers in preference in over 70% of comparisons, most in structured, information-dense domains (ACL Findings 2026); Google's generated pages came close to expert-designed sites and far ahead of raw text. Both are preference measures. — [arXiv 2508.19227](https://arxiv.org/abs/2508.19227); [Google Research blog](https://research.google/blog/generative-ui-a-rich-custom-visual-interactive-user-experience-for-any-prompt/)
- [V] A 2026 paper frames prompt-driven UI generation as two gulfs: users struggle to express intent in prompts (execution) and to understand how the prompt shaped the output (evaluation). — [arXiv 2601.19171](https://arxiv.org/html/2601.19171v1)
- [PK] DirectGPT (CHI 2024; older): direct manipulation plus LLM was 50% faster than chat alone with far shorter prompts. — [arXiv 2310.03691](https://arxiv.org/abs/2310.03691)

**Nielsen Norman Group and Jakob Nielsen**
- [PK] Nielsen (June 2023; older) calls AI the third UI paradigm, "intent-based outcome specification": the user states the result wanted, not the steps. — [NN/g, AI: First New UI Paradigm in 60 Years](https://www.nngroup.com/articles/ai-paradigm/)
- [V] The articulation barrier (Nielsen, 2023; older): it is often hard to put a need into words, especially a non-verbal one; his own estimate (not measured data) is that under 20% of the population in rich countries is articulate enough in writing for advanced prompt-driven use; he predicts successful AI interfaces "will be hybrid", mixing intent-based specification with graphical elements. — [Nielsen, The Articulation Barrier](https://jakobnielsenphd.substack.com/p/prompt-driven-ai-ux-hurts-usability)
- [V] An NN/g study of ChatGPT use found some users "may be unable to add specificity even if they wanted to" because they do not know the vocabulary; helping users add specificity reduces the barrier. — [NN/g, Response outlining](https://www.nngroup.com/articles/response-outlining/)
- [V] NN/g on generative UI (Moran and Gibbons, 2024; older): generative AI brings outcome-oriented design, where designers define user goals and the constraints the AI works within instead of individual interface elements. — [NN/g, Generative UI and Outcome-Oriented Design](https://www.nngroup.com/articles/generative-ui/)
- [PK] NN/g's related pattern articles: prompt controls (buttons and menus that add specificity without typing) and "accordion editing" and "apple picking" (users struggle to adjust and reuse parts of a chat answer). — [NN/g, Prompt Controls in GenAI Chatbots](https://www.nngroup.com/articles/prompt-controls-genai/); [NN/g, Accordion Editing and Apple Picking](https://www.nngroup.com/articles/accordion-editing-apple-picking/)
- [V] Nielsen's later essays ("Intent by Discovery", "No More User Interface?", "AI Use in the Real World: AI's design problem is organisational, not technological") exist; their content was not retrieved. — [Intent by Discovery](https://jakobnielsenphd.substack.com/p/intent-ux); [No More UI?](https://jakobnielsenphd.substack.com/p/no-more-ui); [AI Use in the Real World](https://jakobnielsenphd.substack.com/p/ai-use)

**Practitioner essays**
- [V] Amelia Wattenberger, "Why Chatbots Are Not the Future" (2023; older): a text box has no affordances (its only cue is "type here"), responses are isolated from the work, and partly automated tasks leave a "no man's land" where interface design matters most; chat should gain controls and affordances. Simon Willison called it a convincing case; a 2026 UX Collective piece says the argument "has aged well" ("the chat box isn't a UI paradigm, it's what shipped"). — [Wattenberger](https://wattenberger.com/thoughts/boo-chatbots); [Willison](https://simonwillison.net/2023/May/15/why-chatbots-are-not-the-future); [UX Collective, 2026](https://uxdesign.cc/the-chat-box-isnt-a-ui-paradigm-it-s-what-shipped-96e931d92769)
- [V] Luke Wroblewski (2025): chat is not going away but is receding as agents do more; "Chat is: the Future or a Terrible UI" holds that there is support for both views. — [The Receding Role of AI Chat](https://www.goodreads.com/author_blog_posts/25804020-the-receding-role-of-ai-chat); [Chat is: the Future or a Terrible UI](https://www.goodreads.com/author_blog_posts/26047985-chat-is-the-future-or-a-terrible-ui?tab=book)
- [V] Allen Pike, "Post-Chat UI" (2025), cites Wattenberger's line that we made painting feel like typing when we should have made typing feel like painting, and that a model can talk and show at once. — [Allen Pike](https://allenpike.com/2025/post-chat-llm-ui)
- [V] Geoffrey Litt and Ink & Switch, "Malleable Software" (2025): people need to reshape their tools; AI code generation helps but "is not sufficient on its own"; open question of how AI-generated tools compose over shared data. — [Ink & Switch](https://www.inkandswitch.com/essay/malleable-software/); [Willison's note, 11 Jun 2025](https://simonwillison.net/2025/Jun/11/malleable-software)
- [PK] Maggie Appleton ("Language Model Sketchbook, or Why I Hate Chatbots", 2023; older) and Linus Lee (2023; older) make the same case from the design side: language models should be embedded in purpose-built tools and direct manipulation, not reached only through a chat box. — [Appleton](https://maggieappleton.com/lm-sketchbook); [Lee](https://thesephist.com/posts/latent/)

**Institutional guidance** (all [PK]; the updates search did not run)
- Microsoft's Guidelines for Human-AI Interaction (Amershi et al., CHI 2019; older): 18 guidelines including make clear what the system can do and how well, support efficient invocation, dismissal and correction, scope services when in doubt, make clear why the system did what it did, convey the consequences of user actions, update and adapt cautiously, notify users about changes, provide global controls. — [Microsoft Research](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/)
- Google PAIR People + AI Guidebook (2019, revised since): chapters on user needs and defining success, mental models, explainability and trust, feedback and control, errors and graceful failure. — [PAIR Guidebook](https://pair.withgoogle.com/guidebook/)
- Apple's Human Interface Guidelines gained a generative AI page in 2025; IBM's Carbon for AI standardises an "AI label" with an explanation popover on anything AI-generated. — [Apple HIG, Generative AI](https://developer.apple.com/design/human-interface-guidelines/generative-ai); [IBM Carbon for AI](https://carbondesignsystem.com/guidelines/carbon-for-ai/)
- The Shape of AI (Emily Campbell) catalogues patterns as wayfinders, tuners, governors, trust builders and identifiers. — [Shape of AI](https://www.shapeof.ai/)

### Inferences
- The evidence supports "AI-first" only in the sense of first place to ask, not only place to work. Where the task is "find a figure" or "do this small change", language reduces effort; where it is "compare, check, decide", the dashboard or page wins, and users say so.
- The articulation barrier bites hardest on the roles named in the brief (shift leads, chefs, staff working in a second language). Buttons, suggested actions, prefilled forms and proactive cards are the published remedies; a blank prompt is not.
- Complexity reverses the advantage: design the assistant's best experiences around frequent, simple, well-scoped jobs and hand complex ones to a page.
- The essays by Wattenberger, Appleton, Lee and Wroblewski and the guidance from NN/g and Microsoft all pre-date or run alongside the agent wave, yet the 2026 studies bear them out; nothing found in 2025 to 2026 contradicts the hybrid position.

### Gaps
- NN/g's own 2025 to 2026 usability findings on AI features inside business applications were not found; nngroup.com could not be opened.
- Whether HAX, PAIR or Apple published agent-specific updates in 2025 to 2026 is unconfirmed.
- All controlled studies found use knowledge workers or students at desks. None covers frontline staff on a tablet or phone during service.
- Exact effect sizes for the two industrial studies and the CRUD study were not in the extracts.

## 6. Trust, verification and correction

### Takeaway
Practitioner consensus in 2026 is tiered friction: do and log low-risk reads, preview medium-risk edits, always ask for high-risk or irreversible actions, with undo and an audit trail as first-class controls and a warning against approval fatigue. The empirical point behind it is that users do not self-select caution: they delegate risky operations as readily as safe ones and want a conventional view for verification.

### Cited Findings
- [V] Smashing Magazine (February 2026), "Designing for Agentic AI: Practical UX Patterns for Control, Consent, and Accountability": the preview is "a decision gate rather than a notification", with clear choices and a plain-language summary of actions and outcomes. [PK, unchecked] the article's named patterns are intent preview, autonomy dial, explainable rationale, confidence signal, action audit and undo, and escalation pathway. — [Smashing Magazine](https://smashingmagazine.com/2026/02/designing-agentic-ai-practical-ux-patterns/)
- [V] Tiered friction: "low risk actions like searching are done and logged, medium risk actions like editing show a preview, high risk actions like sending or paying always ask for approval". — [Towards AI, Designing for AI agents: 8 UX patterns that build trust in 2026](https://pub.towardsai.net/designing-for-ai-agents-8-ux-patterns-that-build-trust-in-2026-713a0c926933)
- [V] Undo over approval for frequent low-risk tasks ("undo is more efficient than approval flows"); "approval buttons and undo buttons are the new primary buttons of AI products"; treat an action as irreversible by default unless there is a reliable undo; reversibility is "one of the most practical AI agent guardrails". — [Interaction Patterns guide](https://janrummel.github.io/ai-product-thinking/en/03-product-design/03-interaction-patterns); [Agent builder field guide, HITL](https://rkalani1.github.io/agent-builder-field-guide/safety/hitl/); [DZone](https://dzone.com/articles/human-in-the-loop-approval-enterprise-ai-agents)
- [V] Audit trail contents: what was proposed, what the user decided and when, who approved or rejected, and the role used. Approval fatigue: too much oversight "turns the system into another approval queue". Show the agent's evidence before asking for a one-click approval. — [DZone](https://dzone.com/articles/human-in-the-loop-approval-enterprise-ai-agents); [Level Up Coding, Beyond Approval](https://levelup.gitconnected.com/beyond-approval-designing-human-in-the-loop-control-for-agentic-ai-7b97834bd5ba); [DEV, Show the agent's evidence before asking for one-click approval](https://dev.to/haaaaaley/show-the-agents-evidence-before-asking-for-one-click-approval-1g7d)
- [V] Regulation: commentary notes the EU AI Act's Article 14 requires that people overseeing high-risk systems can override output and stop the system. — [UX Collective, Human in the loop](https://uxdesign.cc/designing-for-ai-human-in-the-loop-means-making-sure-the-human-is-not-out-of-the-loop-e38826309c91)
- [V] Users do not avoid delegating riskier operations (N=73), and in the industrial studies the dashboard "remains valuable for overview and verification" and chat was not preferred as the sole basis for a decision. — [arXiv 2608.19551](https://arxiv.org/pdf/2608.19551); [arXiv 2605.31287](https://arxiv.org/pdf/2605.31287)
- [V] In production: Stripe's assistant makes the change and asks only for a confirm; Salesforce's rule is that a rendered component must not change the meaning of the conversation or restrict the user's choices; MCP forbids collecting secrets through an in-chat form; OpenAI's Apps SDK added per-tool visibility (model, app or both) in July 2026, so some actions can be reachable only from a UI control and not by the model. — [Stripe docs](https://docs.stripe.com/assistant); [Salesforce Engineering](https://engineering.salesforce.com/?p=8181); [MCP spec, Elicitation](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation); [OpenAI Apps SDK changelog](https://developers.openai.com/apps-sdk/changelog)
- [V] Graceful failure in the field: Taco Bell staff monitor nearly every AI order "ready to step in". Trust at the buyer level: 47% of IT leaders lack confidence in managing Copilot's security and access risks. — [eWeek](https://www.eweek.com/news/taco-bell-ai-drive-thru-setbacks/); [Digital Trends](https://www.digitaltrends.com/computing/microsoft-pushed-copilot-everywhere-but-barely-anyone-bought-it-and-even-fewer-use-it-report/)
- [V] Editable plans are a research pattern: Cocoa, "Co-Planning and Co-Execution with AI Agents" (2024; older; title only seen). [PK] Microsoft Research's Magentic-UI (May 2025) implements co-planning (edit the plan before it runs), co-tasking (take over mid-run), action guards (approval for sensitive steps) and plan learning. — [arXiv 2412.10999](https://arxiv.org/pdf/2412.10999); [Microsoft Research, Magentic-UI](https://www.microsoft.com/en-us/research/blog/magentic-ui-an-experimental-human-centered-web-agent/)
- [PK] Anthropic's study of agent use in practice (February 2026) found people approve less step by step as they gain experience (roughly a fifth of sessions on full auto-approve among new users, rising to over two fifths among experienced ones, from memory) while interrupting more: oversight shifts from gating each action to monitoring and stepping in. Coding context. — [Anthropic, Measuring AI agent autonomy in practice](https://www.anthropic.com/research/measuring-agent-autonomy)

### Inferences
- Best practice as of late 2026, assembled from the above: (1) risk tiers set by the product per action, not by the user; (2) a preview that shows the actual change as a before and after, in the same form or card the user would have used; (3) undo for anything reversible, confirm reserved for what is not; (4) every AI-made change recorded with who asked, what was proposed and what was approved; (5) every figure linked to the page or report it came from, so verification happens in the conventional view; (6) a visible way to take over and finish by hand.
- Confirm cards on everything will be rubber-stamped; the studies and the Anthropic data both point to habituation. Fewer, more meaningful confirmations plus undo is the defensible design.
- Because users delegate risky and safe actions alike, destructive operations (delete, anonymise, refund, publish) need friction the assistant cannot waive, such as a typed or two-step confirmation in the GUI.

### Gaps
- Most sources here are practitioner posts, some vendor-affiliated; no authoritative 2026 standard for agent oversight in business software was found.
- No evidence found on how users read uncertainty or confidence displays in business tools, or whether showing provenance changes error detection.
- Details of the Smashing Magazine pattern names and of the Anthropic figures are from memory and need checking.

## 7. Voice and multimodal input

### Takeaway
Dictation and push-to-talk commands are production-ready and spreading in frontline work; open, always-listening voice in a noisy workplace is not dependable, and the restaurant industry's own flagship voice deployments have been slowed or ended. Independent accuracy figures for kitchens do not exist in public: the numbers are vendor claims.

### Cited Findings
- [V] Fast Company reports voice interfaces spreading across factory floors and retail as audio processing makes recognition "less frustrating, even in noisy environments". — [Fast Company](https://fastcompany.com/91642518/voice-ai-is-quietly-transforming-frontline-work)
- [V] Noise is specific: a system tuned for call-centre babble "will not necessarily perform well in a kitchen with fan noise and music playing simultaneously"; accuracy is expected to be high above about 20 dB signal-to-noise; stationary fan noise at 10 dB is "fundamentally easier" than competing speech at 10 dB. Vendor source. — [Picovoice](https://picovoice.ai/blog/noise-robust-voice-ai/)
- [V] Vocabulary matters as much as noise: Deepgram's drive-thru guide says menu vocabulary is the main failure point in production ordering; an aiOla executive says standard models fail in frontline industries on heavy accents, domain vocabulary and constant background noise. Deepgram claims its models hold accuracy through drive-thru and kitchen noise, and markets an in-ear assistant for restaurant staff. Vendor claims, no independent measurement. — [Deepgram, AI drive-thru](https://deepgram.com/learn/ai-drive-thru-voice-ai-order-taking); [Deepgram, restaurants](https://deepgram.com/solutions/restaurants); [aiOla podcast](https://castbox.fm/episode/Voice-AI-for-Frontline-Workers-|-Assaf-Asbag-(Chief-Product-%26-Technology-Officer-at-aiOla)-id6577972-id838693938)
- [V] An unsourced estimate puts recognition at 60% to 70% in moderately noisy environments; treat as weak. — [Patsnap report](https://eureka.patsnap.com/report-optimizing-ai-for-voice-recognition-in-noisy-environments)
- [V] Field record in restaurants: McDonald's ended its IBM drive-thru voice test (2024); Taco Bell slowed its roll-out in 2025 with staff monitoring nearly every order; Wendy's kept expanding. — [NBC News](https://www.nbcnews.com/business/business-news/mcdonalds-end-ai-drive-test-ibm-rcna157603); [eWeek](https://www.eweek.com/news/taco-bell-ai-drive-thru-setbacks/)
- [V] Voice for data maintenance was slower than the GUI in the one small study (204 s against 179 s, N=7). — [arXiv 2505.22303](https://arxiv.org/pdf/2505.22303)
- [PK] Older (2016): dictation about three times faster than typing on a phone, in quiet conditions. — [arXiv 1608.07323](https://arxiv.org/abs/1608.07323)
- [PK] Speech-to-text can invent text: a 2024 study (older) found about 1% of Whisper transcriptions contained hallucinated phrases, more often around pauses. — [arXiv 2402.08021](https://arxiv.org/abs/2402.08021)
- [PK] Real-time speech-to-speech models are generally available (OpenAI's gpt-realtime, August 2025), and speech vendors ship dedicated real-time recognition models. — [OpenAI, Introducing gpt-realtime](https://openai.com/index/introducing-gpt-realtime/); [AssemblyAI, voice agents in noisy environments](https://assemblyai.com/blog/voice-agents-noisy-environments)

### Inferences
- Production-ready for a back office: push-to-talk dictation into a field or the assistant, with the transcript shown before anything is saved; voice confirmation of simple structured checks (a temperature, a tick) where the answer space is small; photo or document capture feeding a form that a person reviews.
- Not dependable: always-listening wake words in a kitchen (competing speech is the worst noise case), free-form voice ordering or multi-field entry without a visual check, and voice as the only route to a destructive action.
- Because recognisers fail on domain vocabulary, feeding the venue's own dish, supplier and staff names to the recogniser or the correcting model is likely to matter more than the choice of model.
- The hallucination finding argues for always showing what was heard and never saving a spoken food-safety or cash figure unseen.

### Gaps
- No independent benchmark of speech recognition in commercial kitchens was found.
- No head-to-head evidence on push-to-talk against always-listening in workplaces; the conclusion above is inferred from the noise evidence.
- Camera and document capture as input (invoices, delivery notes, temperature displays): no user-level evidence gathered; search budget ran out.

## 8. Personalisation, adaptive and malleable interfaces, and the cost of inconsistency

### Takeaway
The vision of interfaces that reshape themselves per user is being pursued (NN/g's generative UI, Salesforce's "dynamic and personal" agentic UI, Ink & Switch's malleable software), but what ships is bounded: role and context decide which approved components appear, or a person generates a custom app once and then keeps it. No evidence was found that per-user, per-visit generated layouts work for operational software, and older research on adaptive menus found they slow people down.

### Cited Findings
- [V] NN/g: generative UI shifts design to outcomes and constraints, with the interface tailored to the individual. [PK] their definition: a UI "dynamically generated in real time by artificial intelligence to provide an experience customized to fit the user's needs and context" (2024; older). — [NN/g, Generative UI](https://www.nngroup.com/articles/generative-ui/)
- [V] Salesforce's stated direction is a "dynamic and personal" agentic UI, delivered through Generative Canvas (approved components, existing permissions) and one UI definition that adapts per surface; most organisations interviewed were still piloting. — [Salesforce Ben](https://www.salesforceben.com/salesforces-vision-for-the-agentic-ui-is-dynamic-and-personal/)
- [V] Ink & Switch (2025): users should be able to adapt tools to their own work; the application model blocks this; AI code generation alone does not solve it, and how generated tools share data and compose is an open problem. Litt's 2026 talk raises "cognitive debt" from agent-written software (mention only; content not retrieved). — [Ink & Switch, Malleable Software](https://www.inkandswitch.com/essay/malleable-software/); [Willison](https://simonwillison.net/2025/Jun/11/malleable-software)
- [PK] Maggie Appleton's "home-cooked software" (2024; older): local experts building small tools for their own community with AI help. — [Appleton](https://maggieappleton.com/home-cooked-software)
- [V] The shipped form of malleability is build once, then stable: Shopify merchants generate a custom admin app, test and refine it, then install it; ServiceNow generates a multi-page experience that a developer then owns; Notion users build agents. — [Shopify Winter '26](https://www.shopify.com/news/winter-26-edition-merchant); [ServiceNow docs](https://www.servicenow.com/docs/r/zUlSbxoxKPAWFDGUdAoSCw/Yh2z7SmzcIlQ4wMpeKqZdQ); [Notion](https://www.notion.com/blog/introducing-custom-agents)
- [V] Run-to-run consistency of free generation: a reviewer of Imagine with Claude got "very similar results" from the same prompt, while another found buttons that did nothing. — [DataCamp tutorial](https://datacamp.com/tutorial/imagine-with-claude); [TestingCatalog](https://www.testingcatalog.com/anthropic-experiments-with-an-agent-for-gereating-ui-on-the-fly)
- [PK] Older (CHI 2004): Findlater and McGrenere compared static, adaptive and adaptable menus; the static menu was faster than the adaptive one, and most participants preferred the adaptable menu they controlled themselves. — [ACM](https://dl.acm.org/doi/10.1145/985692.985704)
- [PK] Microsoft's guideline "update and adapt cautiously" and "notify users about changes" (2019; older) address the same risk. — [Microsoft Research](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/)
- [PK] Arc's makers concluded in 2025 that a product asking users to relearn familiar things for modest reward does not reach beyond enthusiasts. — [Letter to Arc members](https://browsercompany.substack.com/p/letter-to-arc-members-2025)

### Inferences
- For a franchise back office the costs of inconsistency are concrete: staff turn over, people move between venues, area managers support many sites, and help text, training and "do it like this" instructions assume everyone sees the same screen. A layout that differs per user or per visit breaks all of these, and nothing found shows a benefit that outweighs it.
- The defensible forms of personalisation are the ones that keep a stable frame: a role-based home, a feed ordered by what needs doing, remembered filters, and user-controlled (adaptable) arrangement. Generated views belong in clearly marked, disposable places (an answer, a report, a one-off chart) or go through "generate, review, save as a fixed page".
- Generating a form from a platform data model is compatible with consistency if generation is deterministic from the schema and role (same input, same form) and the model only prefills. Letting the model choose the layout each time is what introduces the inconsistency.

### Gaps
- No 2025 to 2026 empirical study was found on learnability, training or support cost of generated or adaptive interfaces in business software; the adaptive-interface evidence cited is two decades old.
- What NN/g says about learnability risk in its generative UI article could not be checked (site not reachable).
- No vendor reports found on role-based or adaptive home screens and their effect on usage.
