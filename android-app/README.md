# Macaroonie Android app

One app (`com.macaroonie.app`) for every device in a restaurant: the till, the
kitchen screen and the self-order kiosk. On its first start it asks what the
device is, then opens that web app full screen:

| Device           | Opens                      |
|------------------|----------------------------|
| Till             | `https://pos.<root>/`      |
| Kitchen screen   | `https://kitchen.<root>/`  |
| Self-order kiosk | `https://kiosk.<root>/`    |

The apps themselves are the `pos/` web build, so they change with every deploy
and never need a new build of this app. The app only adds what a browser can't:

- it starts straight into the right app, full screen, with the status and
  navigation bars hidden and the screen kept on;
- the back button does nothing, and links off the Macaroonie domain stay out
  (a till or kitchen screen opens them in the browser, a kiosk ignores them);
- printing goes to Android's print service (`pos/src/lib/print.js` posts the
  page to the app, which calls `expo-print`);
- the camera works for QR scanning (Android asks for permission the first time);
- if the address can't be reached it says so and tries again every 5 seconds.

To change what a device is: tap the top left corner of the screen five times
quickly (within three seconds). **What is this device?** comes back over the
app, which keeps running underneath: pick another type, **Back to the till**
(no reload) or **Reload the till**. Opened this way it goes back by itself
after a minute nobody touches it. Each type keeps its own link to the
restaurant, so a kiosk switched to a till and back is still linked. The taps
are counted by `corner.js`, injected into every page (they still reach the
page) and natively while a page loads. A device that isn't linked yet also
has **Change device type** on its setup screen.

## Building

Built and signed by EAS (Expo project `@gomono-london/macaroonie`). The
GitHub connection on expo.dev must point at this repository with the base
directory `android-app`.

- `preview`: an APK to install on devices by hand (share the link EAS gives).
- `production`: also an APK to install by hand, for now. **Build from GitHub**
  on expo.dev doesn't ask for a profile or platform: it builds every platform
  with `production`. The iOS build fails (the app is Android only); cancel it.
  When the app goes on Google Play, set `production` back to
  `"buildType": "app-bundle"` without `"distribution": "internal"`.
- `development`: an APK whose WebView can be inspected from Chrome
  (`chrome://inspect`).

`MACAROONIE_ROOT_DOMAIN` (build environment) points a build at another
address, for a test server; the default is `macaroonie.com`.

## Checking a change

```bash
npm ci
npm test
npx expo config --type public
npx expo export --platform android
```

The GitHub workflow `.github/workflows/android-app.yml` runs the same on every
pull request that touches this folder. The `android/` folder is generated by
EAS on each build (Continuous Native Generation): never commit it; change
native settings in `app.json` and its plugins.
